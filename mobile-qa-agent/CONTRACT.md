# Контракт агента (этап 14.1)

Формальная спецификация входа, выхода и политик. `SKILL.md` — операционная
инструкция для самого агента; этот файл — контракт для того, кто агента
запускает и оценивает.

## Вход

| Поле | Источник | Обязательно |
| --- | --- | --- |
| задача или charter | `instruction` case-манифеста | да |
| приложение | `appId` манифеста | да |
| платформа | флаг `--platform` (ровно одна на run) | да |
| build | version manifest снимает автоматически (commit + dirty) | да |
| project adapter | поле `adapter` манифеста; по умолчанию `qalab` | да |
| policy | `allowedActions`, `forbiddenActions`, `limits` манифеста | да |
| устройство | флаг `--device` | да |

Агент получает вход **напечатанным** командой `harness.mjs start`: задание,
разрешённые и запрещённые действия, лимиты. Отдельного канала нет — это
гарантирует, что агент видит ровно то, что записано в манифесте.

## Выход

| Артефакт | Кто формирует |
| --- | --- |
| структурированный verdict `PASS`/`FAIL`/`BLOCKED`/`INCONCLUSIVE` | oracle, не агент |
| evidence pack (version manifest, initial/final UI + screenshot, состояние до/после, transcript) | harness автоматически |
| классификация результата по taxonomy | агент при неуспехе, ревьюит человек |
| draft дефекта | агент, **без публикации** |
| отчёт из 27 полей (Приложение B) | harness, содержательные поля от агента |

## Политики

**Retry budget.** Не более трёх попыток одного бизнес-действия. Смена селектора
или координат — новая попытка того же действия. После исчерпания — остановка,
сохранение evidence, эскалация.

**Stop conditions.** Crash (`PROCESS DISAPPEARED`); исчерпание retry;
превышение `limits.timeoutSeconds`; потеря контроля (неизвестный экран,
пропавшее устройство, расхождение UI и состояния); требование действия из
запрещённого списка.

**Human approval.** Требуется до: любого destructive-действия вне явного плана
сценария; любого шага с учётными данными (агент их вообще не выполняет);
публикации чего-либо вовне. Подтверждение запрашивается остановкой run, а не
продолжением «на свой риск».

**Очистка данных.** Teardown выполняется при любом исходе. Что именно чистить,
знает project adapter: QA Lab удаляет записи и возвращает proxy в passthrough,
Speecher останавливает приложение и сбрасывает системные разрешения, Element X
останавливает приложение (данные одноразового локального сервера не удаляются
намеренно — проверки построены на разнице состояний).

## Чек-лист контракта (14.1)

- [x] Агент принимает только одну целевую платформу на run — `--platform`
  обязателен, манифест с `platform: ios` не стартует на android (проверка в
  `cmdStart`).
- [x] Агент выполняет preflight до первого действия — раздел «Порядок работы»
  в `SKILL.md`; `harness.mjs start` фиксирует исходное состояние и падает, если
  снимок устройства снять не удалось.
- [x] Агент проверяет, что наблюдает нужное приложение — первая строка `ui`
  содержит имя приложения, сверка предписана `SKILL.md`.
- [x] Агент следует циклу observe → act → verify — правило 3 в `SKILL.md`.
- [x] Агент использует зафиксированный приоритет selectors — раздел «Приоритет
  селекторов», пять уровней.
- [x] Агент не считает exit code действия бизнес-подтверждением — правило 1,
  вынесено первым.
- [x] Агент создаёт отдельный Workspace или test namespace — `createContext`
  адаптера на каждый run.
- [x] Агент использует сменный API oracle adapter — поле `adapter` манифеста,
  три реализации.
- [x] Агент сохраняет обязательные evidence — автоматически, полнота
  проверяется полем `evidenceComplete`.
- [x] Агент останавливается при crash и сохраняет состояние — правило 7.
- [x] Агент эскалирует после исчерпания retry budget — правило 6.
- [x] Агент запрашивает подтверждение destructive action — раздел «Запрещено».
- [x] Агент выполняет teardown даже после неуспеха — правило 8, проверено на
  намеренно прерванном run (selftest).
- [x] Агент формирует draft дефекта, но не публикует его — раздел «Draft
  дефекта».
- [x] Агент различает product, environment, tool, accessibility, oracle и agent
  failures — раздел «Классификация неуспеха» + `failure-taxonomy.md`.

## Что в контракте намеренно отсутствует

**Обещание автономности.** Контракт описывает, как агент работает и что
доказывает, но не утверждает, что он справится без человека. Автономность —
предмет измерения подэтапа 14.D, а не декларация.

**Обещание экономии времени.** Тот же принцип: сравнение с ручным baseline —
измерение, а не свойство контракта.
