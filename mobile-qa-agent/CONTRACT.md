# Контракт агента

Формальная спецификация входа, выхода и политик. `SKILL.md` — операционная
инструкция для самого агента; этот файл — контракт для того, кто агента
запускает и оценивает.

Исходная версия принята на этапе 14.1. Текущая ревизия дополнена 7 августа
2026 года по результатам прогонов на физическом Android; новые правила требуют
отдельного перепрогона, перечисленного в `evals/README.md`.

## Вход

| Поле | Источник | Обязательно |
| --- | --- | --- |
| задача или charter | `instruction` case-манифеста | да |
| приложение | `appId` манифеста | да |
| платформа | флаг `--platform` (ровно одна на run) | да |
| build | version manifest снимает автоматически (commit + dirty) | да |
| project adapter | поле `adapter` манифеста; по умолчанию `qalab` | да |
| policy | `allowedActions`, `forbiddenActions`, `limits` манифеста | да |
| устройство | флаг `--device` | да |

Агент получает вход **напечатанным** командой `harness.mjs start`: задание,
разрешённые и запрещённые действия, лимиты. Отдельного канала нет — это
гарантирует, что агент видит ровно то, что записано в манифесте.

## Выход

| Артефакт | Кто формирует |
| --- | --- |
| структурированный verdict `PASS`/`FAIL`/`BLOCKED`/`INCONCLUSIVE` | oracle, не агент |
| evidence pack (version manifest, initial/final UI + screenshot, состояние до/после, transcript) | harness автоматически |
| классификация результата по taxonomy | агент при неуспехе, ревьюит человек |
| draft дефекта | агент, **без публикации** |
| отчёт из 27 полей (Приложение B) | harness, содержательные поля от агента |

## Политики

**Retry budget.** Не более трёх попыток одного бизнес-действия. Смена селектора
или координат — новая попытка того же действия. После исчерпания — остановка,
сохранение evidence, эскалация.

**Stop conditions.** `PROCESS DISAPPEARED`, классифицированный harness как
целевой или неясный процесс (подтверждённый чужой процесс при живом целевом
приложении журналируется, но не останавливает run); исчерпание retry;
превышение `limits.timeoutSeconds`; потеря контроля (неизвестный экран,
пропавшее устройство, расхождение UI и состояния, возможная мутация соседнего
поля); требование действия из запрещённого списка; потеря журналирующей
обёртки или доступа к рабочему каталогу.

**Адресат ввода (R-65).** Успешный `type`, флаг `focused` и число отправленных
графем MUST NOT считаться доказательством попадания текста в целевое поле.
После ввода агент MUST проверить `value` именно этого поля, связанный счётчик
символов или иной независимый наблюдаемый признак. Если значение недоступно,
продолжение допустимо только когда напечатанный вход run явно гарантирует
точную независимую проверку каждого поля финальным oracle; недоказанный шаг
фиксируется явно. Без такого условия во входе результат считается
недоказанным. Пустое целевое поле или возможное изменение соседнего означает
потерю контроля и остановку без попытки «исправить» форму дополнительным
вводом.

**Прокрутка и адресация (R-67/R-68).** Неизменившееся accessibility-дерево
после swipe MUST NOT использоваться для диагноза «жест начат вне scroll-view»:
так же выглядят короткий/перехваченный жест и устаревший снимок. На физическом
Android первый снимок после swipe считается потенциально устаревшим и агент
читает как минимум следующий; никакое фиксированное число повторов само по
себе не доказывает свежесть. Стабильный ID MUST быть первым путём к адресуемому
контролу. Координата из дерева после прокрутки или во время анимации не является
fallback; без согласования со screenshot координатное действие запрещено.

**Средовые сигналы (R-63/R-69/R-70).** `keyboard-state` является advisory, а
не доказательством видимости IME. Агент сверяет viewport по дереву и screenshot;
если IME могла вытеснить поле, скрывает её и заново наблюдает форму до вывода
об отсутствии элемента. Потеря журналирующей обёртки или TCC-доступа даёт
`BLOCKED/environment`: агент вызывает штатный abort, когда он доступен, и MUST
NOT продолжать прямыми незажурналированными командами `sim-use`/`adb`.

**Human approval.** Требуется до: любого destructive-действия вне явного плана
сценария; любого шага с учётными данными (агент их вообще не выполняет);
публикации чего-либо вовне. Подтверждение запрашивается остановкой run, а не
продолжением «на свой риск».

**Очистка данных.** Teardown MUST выполняться при любом исходе. Что именно
чистить, знает project adapter: QA Lab удаляет записи и возвращает proxy в
passthrough, Speecher останавливает приложение и сбрасывает системные
разрешения, Element X останавливает приложение (данные одноразового локального
сервера не удаляются намеренно — проверки построены на разнице состояний).
Явные `finish`/`abort` пути проверены, но гарантированное выполнение при любом
исключении lifecycle остаётся открытым implementation debt, отражённым ниже.

## Чек-лист контракта (14.1)

- [x] Агент принимает только одну целевую платформу на run — `--platform`
  обязателен, манифест с `platform: ios` не стартует на android (проверка в
  `cmdStart`).
- [x] Агент выполняет preflight до первого действия — раздел «Порядок работы»
  в `SKILL.md`; `harness.mjs start` фиксирует исходное состояние и падает, если
  снимок устройства снять не удалось.
- [x] Агент проверяет, что наблюдает нужное приложение — первая строка `ui`
  содержит имя приложения, сверка предписана `SKILL.md`.
- [x] Агент следует циклу observe → act → verify — правило 3 в `SKILL.md`.
- [x] Агент использует зафиксированный приоритет selectors — раздел «Приоритет
  селекторов», пять уровней.
- [x] Агент не считает exit code действия бизнес-подтверждением — правило 1,
  вынесено первым.
- [ ] Агент создаёт отдельный Workspace или test namespace на каждый run — это
  обязательное требование (MUST), но текущая реализация QA Lab переиспользует
  UUID с экрана. Несоответствие открыто; галочка вернётся только после правки и
  наблюдаемого прогона со свежим namespace.
- [x] Агент использует сменный API oracle adapter — поле `adapter` манифеста,
  три реализации.
- [x] Агент сохраняет обязательные evidence — автоматически, полнота
  проверяется полем `evidenceComplete`.
- [x] Агент останавливается при crash и сохраняет состояние — правило 7.
- [x] Агент эскалирует после исчерпания retry budget — правило 6.
- [x] Агент запрашивает подтверждение destructive action — раздел «Запрещено».
- [ ] Teardown гарантирован после любого неуспеха — правило 8 обязательно и
  явный `abort` проверен, но исключения capture/readState/oracle ещё могут
  обойти cleanup, потому что весь lifecycle не защищён `finally`.
- [x] Агент формирует draft дефекта, но не публикует его — раздел «Draft
  дефекта».
- [x] Агент различает product, environment, tool, accessibility, oracle и agent
  failures — раздел «Классификация неуспеха» + `failure-taxonomy.md`.

### Проверка ревизии от 7 августа

- [ ] Живой smoke подтверждает `foreign → continue` и `target/unclear → stop`
  для crash guard (`R-59/R-64`) с сохранённым command/evidence; модульное
  покрытие уже есть, committed post-fix physical smoke отсутствует.
- [ ] Холодный eval подтверждает остановку при расхождении адресата ввода
  (`R-65`), включая возможную мутацию соседнего поля.
- [ ] Физические `C1` и `C3` подтверждают правила устаревшего дерева,
  стабильного ID и viewport после IME (`R-67`–`R-69`).
- [ ] Средовой eval подтверждает `BLOCKED/environment` при потере
  журналирующей обёртки/TCC без прямых незаписанных команд (`R-70`).

Это checklist наблюдаемого поведения, а не наличия текста в `SKILL.md`.
Правила уже обязательны, но `[x]` появится только после нового cold/physical
evidence.

## Что в контракте намеренно отсутствует

**Обещание автономности.** Контракт описывает, как агент работает и что
доказывает, но не утверждает, что он справится без человека. На одном коротком
run измерено `B=0`, но один замер не является общей гарантией автономности.

**Обещание экономии времени.** Тот же принцип: сравнение с ручным baseline —
измерение, а не свойство контракта. Замер `M1` нельзя напрямую сравнивать с
270 минутами ручного исследования: scope различается.
