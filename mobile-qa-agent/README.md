# mobile-qa-agent

Собственный QA-агент этапа 14. Закрепляет **подтверждённые** практики
исследования, а не предположения его начала.

## Что это и чего это не

Агент — это **инструкция плюс контур**, а не отдельная программа. Исполняемая
часть (изоляция данных, seed, oracle, evidence, teardown, метрики) уже
построена в `../harness`. На 7 августа 2026 ledger содержит 89 записей: 71
`PASS`, 12 `FAIL`, 5 `BLOCKED`, 1 `INCONCLUSIVE`; 56 на iOS и 33 на Android.
Это накопленная история, а не единый однородный benchmark:
`evidenceComplete: true` имеют 64 записи, `false` — одна, а 24 legacy-записи
поля не имеют. Агент добавляет к контуру операционный контракт и правила
принятия решений.

Строить исполняемую часть заново было бы ошибкой: контур проверялся
selftest'ом и тремя приложениями. Текущая suite содержит 202 проверки; 176
offline-проверок после CHG-002 прошли, а 26 проверок живого цикла требуют
доступа к локальному backend 8890 и ещё не перепройдены в этой ревизии. Это не
является end-to-end подтверждением новой ревизии правил агента.

## Запуск одного прогона

Предусловия: поднято ровно одно целевое устройство; для QA Lab — backend на
8890 и fault proxy приложения на 8888, для Element X — локальный Synapse. UTF-8
локаль обязательна:

```bash
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
```

```bash
cd harness
WS=$(node harness.mjs new-workspace)  # сначала задайте этот UUID в QA Lab UI
node harness.mjs start --case <caseId> --platform <ios|android> \
     --device <id> --workspace "$WS" \
     --model "<модель>" --skill "mobile-qa-agent@<версия>"
# агент выполняет задание, вызовы — через node sim.mjs --run <runId> -- …
node harness.mjs finish --run <runId> --self-report "…" --knowledge "…"
```

`--workspace` в этом примере относится к QA Lab; у других adapter нет
Workspace и прямого REST-oracle на 8890.

`start` сам выполняет `prepare`, затем `preflight`. Свежий изолированный
контекст на run остаётся обязательным: автоматическое переиспользование QA Lab
Workspace с экрана — известное несоответствие реализации, а не допустимая
замена этого правила. Для QA Lab перед `start` создайте UUID командой
`node harness.mjs new-workspace`, задайте его в приложении и добавьте к `start`
флаг `--workspace <UUID>`; для остальных адаптеров этот флаг неприменим.
QA Lab adapter по умолчанию направляет seed/oracle/teardown прямо на 8890.
`ORACLE_BASE_URL` задаётся только для другого прямого HTTP backend; локальный
fault proxy на 8888 в этом поле запрещён.

Прерывание: `node harness.mjs abort --run <runId> --reason "…"`.

Метрики серии: `node harness.mjs summary --stage <N>`.

## Известные ограничения

Список того, что **не обходится** переформулировкой задания, —
`../docs/knowledge/hard-limits.md`. Кратко: нет звука на симуляторе,
зашифрованное содержимое недоступно oracle, транзиентные состояния недоказуемы
финальным evidence, iOS wheel-picker не отдаёт значение, чистый контекст нельзя
сымитировать инструкцией.

## Статус

Подэтапы 14.A–14.E завершены; формальный итог исследования — **`PIVOT`**.
Постплановые артефакты 4–7 августа лежат в техническом namespace `stage-16`,
который не является новым этапом плана.

Отсутствие участия во время выполнения (`B=0`) измерено на одном коротком run:
`A=4`, `C=15`, всего 19 человеко-минут. Экономия времени на сопоставимом scope
не доказана: 270 минут ручного исследования покрывали существенно более
широкую область, а короткий M1 вручную оценён примерно в 3 минуты. Поэтому
агента корректно представлять как усилитель/второй проход с независимым oracle,
а не как доказанную замену ручному QA.

`R-19` закрыт прогонами на одном Samsung SM-S931B / Android 15: пять попыток,
3 `PASS`, 1 `FAIL`, 1 `BLOCKED`; четыре зачтённых результата — 3 `PASS`, 1
`FAIL`. Это подтверждает применимость на конкретном телефоне, но не широкую
поддержку физических устройств и не полный recovery-набор этапа 4.3.

Правила `R-59`/`R-64`/`R-65`/`R-67` и fail-closed поведение при потере wrapper
записаны и структурно проверяются, но новая ревизия `SKILL.md` ещё не
подтверждена новым cold-context/physical end-to-end прогоном. Открытый набор
повторной проверки — в [evals/README.md](evals/README.md).
