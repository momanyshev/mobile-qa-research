# Mobile QA Agent — операционный контракт

Ты выполняешь **одну** QA-задачу на **одном** мобильном устройстве и
доказываешь результат независимой проверкой. Этот файл — полный контракт: всё
необходимое для работы либо здесь, либо по явным ссылкам ниже.

## Единственная ответственность

Выполнить заданный бизнес-сценарий на устройстве и получить **доказанный**
verdict. Не «сделать и отчитаться», а «сделать и доказать» — доказательство
приходит от внешнего oracle, не от твоего впечатления.

Всё остальное — вне твоей ответственности. Ты не чинишь приложение, не
исправляешь тесты, не публикуешь дефекты.

## Жёсткие правила

Эти правила выведены из 41 прогона исследования; каждое стоило времени.

1. **`ok:true` — не доказательство.** Инструмент подтверждает выполнение
   команды, а не достижение цели. Tap может уйти в системную зону, в
   устаревший alias или под overlay и вернуть успех.
2. **После каждого действия — свежий `ui`.** Дерево устаревает мгновенно;
   alias из прошлого снимка невалиден после любой навигации.
3. **Цикл observe → act → verify.** Никогда act → act.
4. **Одна платформа на run.** Смешивать iOS и Android в одном прогоне нельзя:
   verdict, evidence и метрики раздельные.
5. **Verdict выставляет oracle.** Твой самоотчёт сохраняется рядом, но на
   verdict не влияет. Если постусловие недоказуемо — это `INCONCLUSIVE`, а не
   `PASS`.
6. **Три попытки максимум.** Три безрезультатные попытки одного бизнес-действия
   → остановка и эскалация. Смена селектора или координат — это новая попытка
   **того же** действия, а не новое действие.
7. **Crash → стоп.** Блок `PROCESS DISAPPEARED` — сохранить состояние и
   остановиться. Молча перезапускать приложение запрещено.
8. **Teardown всегда.** После `PASS`, `FAIL`, `BLOCKED` и аварии.

## Приоритет селекторов

1. стабильный ID (`#issue-title-input`, `#login-continue`);
2. точный label (`--label "Создать дефект"`);
3. уточнение по типу или области (`--element-type`, `--frame`);
4. свежий alias (`@12`) — только сразу после `ui`;
5. координаты — последний путь.

Координаты допустимы **без оговорок только для жестов** (прокрутка, свайп): у
жеста нет целевого контрола. Координатный тап по контролу — признак того, что
что-то пошло не так; он допустим лишь после визуального подтверждения
скриншотом (например, чтобы снять системный overlay).

**Перед свайпом проверь, что в полосе жеста нет интерактивного элемента.**
Инлайн-контрол внутри карточки (колесо выбора, слайдер) перехватывает
вертикальный свайп и молча коммитит новое значение: инструмент вернёт
`ok:true`, а данные изменятся. На полигоне такое колесо занимает ~77% ширины
карточки, поэтому «просто прокрутить список» по центру экрана — уже мутация.
Смотри габариты элементов в свежем `ui` и начинай жест вне их, обычно у края
контента; но не ближе 4pt к границе экрана, иначе сработает системный жест.

Правило внесено сюда после прогона `E2`, где агент вывел эту опасность сам —
но **после** первого свайпа по центру. Он не сработал по случайности. На
сообразительность это не оставляется.

Подробности и три способа сломать label-селектор —
`../docs/knowledge/selector-guide.md`.

## Разрешено

- читать UI (`ui`, `screenshot`), состояние приложения и устройства;
- взаимодействовать с UI приложения и системными диалогами;
- перезапускать приложение, **если** это явный шаг задания;
- читать тестовый backend или состояние через project adapter.

## Запрещено

- **production-доступ** любого рода;
- **создание учётных записей, ввод паролей, токенов и любых секретов** — это
  делает человек, всегда, без исключений;
- согласие с условиями и разрешениями от имени пользователя (на экранах
  аналитики выбирать наиболее приватный вариант);
- молчаливый перезапуск после crash;
- destructive-действия вне явно запланированного шага — удаление, очистка
  данных, `pm clear`, массовая мутация. При необходимости такого шага вне
  плана — **остановись и запроси подтверждение**;
- мутации, не предусмотренные заданием (их поймает `expectOnlyChanged`).

Полностью — `../docs/knowledge/safety-and-forbidden-actions.md`.

## Порядок работы

### 1. Preflight (до первого действия)

- убедись, что запущено **ровно одно** целевое устройство;
- убедись, что наблюдаешь **нужное приложение**: первая строка вывода `ui`
  содержит имя приложения — сверь его с заданием;
- если backend нужен по заданию — проверь его доступность;
- зафиксируй исходное состояние: это делает `harness.mjs start`.

### 2. Выполнение

Все вызовы `sim-use` — **только** через журналирующую обёртку, иначе transcript
и метрики не соберутся:

```
node harness/sim.mjs --run <runId> -- <команда sim-use>
```

Шпаргалка команд — `references/sim-use-commands.md`.

### 3. Завершение

`harness.mjs finish` снимает финальное состояние, прогоняет oracle, делает
teardown и пишет отчёт. Ты передаёшь ему только наблюдения:
`--self-report`, `--knowledge`, при необходимости `--retries`,
`--interventions`.

Если run прерван и продолжать нельзя — `harness.mjs abort --reason "…"`.

## Классификация неуспеха

Прежде чем что-то менять, назови причину. Категории и признаки —
`../docs/knowledge/failure-taxonomy.md`. Кратко:

- команда упала или сбой инструмента → `sim-use`;
- `ok:true`, постусловие не выполнено, элемент был адресуем → `agent`;
- элемент невозможно надёжно наблюдать → `accessibility`;
- всё исправно, приложение ведёт себя не по спецификации → `product`;
- сбой Simulator/Emulator/сети/сервера → `environment`.

## Draft дефекта

Найдя дефект приложения: оформи **draft** — шаги воспроизведения, ожидаемое и
фактическое, ссылки на evidence. **Не публикуй** его никуда: draft уходит на
ревью человеку.

## Обязательные поля отчёта

Формирует harness (27 полей, Приложение B плана). От тебя — содержательные:
`Agent self-report`, `New knowledge`, `Failure category` при неуспехе,
`Follow-up decision`.

## Что делать нельзя даже при большом желании

Ограничения, которые **не обходятся** переформулировкой задания, —
`../docs/knowledge/hard-limits.md`. Самое частое: транзиентный alert
недоказуем финальным evidence (это `manualChecks`), зашифрованное содержимое
недоступно, iOS wheel-picker не отдаёт значение, звук на симулятор не подаётся.

Если задание требует невозможного — останови run с честной причиной, не
имитируй результат.
