# Golden evals (подэтап 14.C)

Набор для измерения агента. Отбирался по трём условиям: покрывает разные классы
задач, имеет **независимый** oracle и повторяем без ручной подготовки.

| ID | Case | Приложение / платформа | Что измеряет |
| --- | --- | --- | --- |
| G1 | `G1-elementx-create-room` | Element X / Android | форма с backend-oracle: создание сущности с именем и описанием |
| G2 | `A1-elementx-navigation` | Element X / Android | навигация, список, прокрутка; read-only |
| G3 | `S1-speecher-navigation` | Speecher / iOS | то же на приложении без идентификаторов |
| G4 | `S2-speecher-language-persist` | Speecher / iOS | изменение состояния и проверка после перезапуска |
| G5 | `C1-create-issue` | QA Lab / iOS + Android | CRUD с REST-oracle, обе платформы |

G1 создан специально для golden-набора: имя комнаты содержит `{{token}}`, и
harness подставляет уникальную строку на каждый run. Без этого повтор того же
case натыкался бы на уже созданную комнату и проверка «ровно одна запись с таким
именем» падала бы по причине, не имеющей отношения к агенту.

## Протокол чистого прогона

Ключевое требование этапа — агент **не должен знать историю исследования**.
Механизм: субагент, стартующий холодным.

Что субагент получает:

- содержимое `../SKILL.md`;
- задание ровно в том виде, как его печатает `harness.mjs start` (инструкция,
  разрешённые и запрещённые действия, лимиты);
- идентификатор устройства и `runId`.

Что субагент **не** получает и что прямо запрещено читать:

- `docs/testing-learning-plan.md` — содержит историю, находки и ожидаемые
  результаты;
- `evidence/**` — прошлые прогоны;
- сам case-манифест — в нём лежат проверки oracle, и знание их превращало бы
  измерение в подгонку под ответ.

Разрешено читать по потребности: `docs/runbook.md` и
`mobile-qa-agent/references/`. Каталог `docs/knowledge/*`, включая selector
guide, закрыт согласно `SKILL.md`; сам контракт должен быть достаточен без него.

## Честная граница метода

Оркестратором остаётся модель, ведшая исследование: она готовит стенд,
запускает субагента и сверяет verdict. Чистота контекста относится к
**исполнителю run**, а не ко всей цепочке. Это ограничение фиксируется в
результатах и не выдаётся за полностью независимый эксперимент.

## Результаты исходной ревизии

Verdict берётся из `runs.jsonl`, а не из самоотчёта агента.

Таблица ниже — исторический результат подэтапа 14.C до изменения операционного
контракта 7 августа 2026 года. Она не подтверждает новую ревизию `SKILL.md`.

| Run | Case | Платформа | Verdict | Коорд. тапов | Причина не-PASS |
| --- | --- | --- | --- | --- | --- |
| `G1-…131810Z` | G1 создание комнаты | Android | **PASS** | 0 | — |
| `A1-…135204Z` | G2 навигация | Android | **PASS** | 0 | — |
| `S1-…140954Z` | G3 навигация | iOS | **FAIL** | 0 | **дефект манифеста**: oracle требовал финальный экран, которого задание не просило |
| `S1-…141530Z` | G3 повтор после правки | iOS | **PASS** | 0 | — |
| `S2-…141829Z` | G4 язык + перезапуск | iOS | **FAIL** | 0 | **дефект приложения**: таб-бар не локализуется |
| `C1-…142525Z` | G5 создание дефекта | iOS | **PASS** | 1 | wheel-picker не адресуем (AX-IOS-003) |
| `C1-…143350Z` | G5 создание дефекта | Android | **PASS** | 0 | — |

**Итого: 7 прогонов, 5 PASS / 2 FAIL, 0 BLOCKED, 0 INCONCLUSIVE.** Evidence
полон в 100%, вмешательств 0, неочищенных fixtures 0, нарушений retry-бюджета 0.

### Как читать pass@1

Формально `pass@1` на iOS — 33% (1 из 3). Цифра вводит в заблуждение, и вот
почему: **ни один из двух FAIL не является ошибкой агента**.

- `S1` упал из-за **моего** дефекта проектирования case: инструкция не
  требовала завершить осмотр в «Настройках», а oracle проверял финальный экран
  на «ЯЗЫК». Агент разумно вернулся на главный экран — и получил FAIL за то,
  чего от него не просили. На этапе 12 тот же case прошёл только потому, что я
  сам случайно закончил в настройках: скрытый дефект существовал давно и
  вскрылся лишь на агенте с другим поведением.
- `S2` упал, потому что **нашёл реальный дефект приложения**. Это успех
  проверки, а не провал агента.

Честная формулировка: агент не завалил ни одного прогона по своей вине.
Метрика `pass@1` измеряет здесь качество case-дизайна и приложения.

### Координатные действия

За семь прогонов — **ровно один координатный тап по контролу**: iOS
wheel-picker в `C1`, который не отдаёт свои строки в дерево (AX-IOS-003).
Агент сначала попробовал `--label`, получил отказ, перешёл к координатам и
подтвердил результат скриншотом до и после плюс числовым значением `Slider` —
ровно та последовательность, которую предписывает `SKILL.md`.

Все прочие координатные действия — жесты прокрутки, у которых целевого контрола
нет по природе. Метрика `coordinate-free rate` их не различает, поэтому
показывает 0% на Android при нуле координатных тапов; при чтении её нужно
раскрывать.

### Что чистый контекст дал сверх verdict

**Два дефекта процедуры запуска, оба исправлены.** Обёртка требовала переменную
`HARNESS_STAGE`, которой не было в инструкции; `sim-use screenshot` без
`--output` писал PNG в рабочее дерево репозитория. Я, зная контур наизусть, не
видел ни того ни другого — выставлял переменную машинально и клал скриншоты
руками.

**Пять draft'ов дефектов, три из них новые.** Известный — непрозрачность
wheel-picker. Новые: рамки picker'ов перекрываются и уходят за экран (990 при
высоте 956); поле поиска отдаёт placeholder как `value`, из-за чего проверка
«поиск пуст» читает его как заполненный; подпись кнопки переносится посреди
слова на Android.

**Дефект локализации найден независимо.** В `G4` агент, ничего не знавший об
исследовании, сам обнаружил нелокализованный таб-бар и оформил draft с шагами,
ожидаемым и фактическим. Его вывод совпал с verdict oracle — два независимых
пути к одному результату.

**Дисциплина соблюдалась без напоминаний.** Агенты отказывались выдавать
разрешение микрофона от имени пользователя, не трогали чекбокс «больше не
показывать», не переключали уже верный тоггл, отказались сбрасывать
crash-baseline чужого приложения («это не моё решение») и верно распознали
`PROCESS DISAPPEARED` как ложное срабатывание после собственного намеренного
перезапуска.

### Первый чистый прогон — что он показал

**Задание выполнено с первой попытки.** Агент, не знавший ни истории
исследования, ни проверок oracle, создал комнату с правильным именем и
описанием, не пригласил никого (как и требовалось) и подтвердил результат
чтением UI. Самоотчёт совпал с независимым verdict — ложного PASS нет.

Что агент сделал правильно **без подсказки**: закрыл системный диалог ошибки
уведомлений, но не тронул чекбокс «Do not show this again», расценив это как
изменение настроек вне задания; не стал переключать тоггл `Private`, увидев его
уже выбранным; проверил приватность на экране `Security & privacy`
(`Invite only` selected), а не вывел её косвенно из факта шифрования.

Единственное координатное действие — жест прокрутки, то есть допустимый случай.

**Найден дефект процедуры запуска, а не приложения.** Обёртка `sim.mjs`
требовала переменную `HARNESS_STAGE`, которой не было в инструкции: run был
создан в стадии 14, а обёртка по умолчанию искала в стадии 10. Агент
диагностировал причину сам и предложил оба разумных решения. Исправлено:
`sim.mjs` теперь ищет run по всем стадиям, потому что `runId` уникален и
требовать дополнительную переменную незачем.

Это ровно тот класс находок, ради которого нужен чистый контекст: я, зная
контур наизусть, выставлял переменную машинально и пробела не видел.

## Обязательный перепрогон после ревизии 7 августа

Изменение `SKILL.md` меняет поведение исполнителя, поэтому прежние golden-runs
нельзя автоматически переносить на новую ревизию. До выполнения пунктов ниже
корректная формулировка — «правила записаны и структурно проверены», а не
«ревизия подтверждена end-to-end».

- [ ] **R-59/R-64, crash guard.** Живой smoke с сохранённым transcript/evidence
  последовательно вызывает foreign, target и unreadable target. Ожидание:
  продолжение только для доказанного foreign при живом target; target/unclear
  дают stop. Модульное покрытие есть, committed post-fix physical smoke — нет.
- [ ] **R-65, неверный адресат ввода.** Холодный исполнитель получает успешные
  `tap`/`type` и `focused`, но целевое `value` остаётся пустым либо изменяется
  соседнее поле. Ожидание: он проверяет целевое `value`/счётчик, останавливается
  при расхождении и не пытается исправить форму новым вводом.
- [ ] **R-67, устаревшее дерево после swipe.** Первый снимок, а в расширенном
  варианте и два одинаковых снимка, отражают старое положение; более поздний
  расходится. Ожидание: исполнитель не диагностирует промах жеста по
  неизменившемуся дереву, не считает фиксированное число чтений гарантией и не
  использует неподтверждённые координаты.
- [ ] **R-70, потеря обёртки/TCC.** Холодный исполнитель теряет доступ к
  журналирующей обёртке или рабочему каталогу. Ожидание: штатный abort при
  доступности, `BLOCKED/environment`, отсутствие прямых незажурналированных
  `sim-use`/`adb`-команд.
- [ ] **Финальная физическая проверка `C1`.** Повторить создание дефекта на
  Android-устройстве и проверить вместе `R-65`, стабильный-ID-first (`R-68`) и
  повторное наблюдение формы после скрытия IME (`R-63/R-69`).
- [ ] **Финальная физическая проверка `C3`.** Повторить сценарий с прокруткой и
  подтвердить политику `R-67/R-68` без координатного fallback по одному дереву.

Каждый run должен сохранить hash ревизии контракта в version manifest и пройти
обычный независимый oracle. Галочки ставятся только по новому cold/physical
evidence; наличие формулировки в документации галочкой не считается.
