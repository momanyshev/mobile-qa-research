# Mobile QA Research: sim-use

Исследование пригодности инструмента `sim-use` как основы автономного
мобильного QA-агента для iOS и Android. Здесь живут план исследования,
доказательства (evidence), заметки по инструменту и — начиная с этапа 14 —
собственный AI-агент.

Это исследование **инструмента**, а не приложения. Приложения, на которых
выполняются прогоны, — внешний стенд: они не разрабатываются здесь, и их
дефекты и функционал не являются предметом этого проекта.

## Структура

Полное оглавление репозитория — в [AGENTS.md](AGENTS.md). Коротко:

- `docs/testing-learning-plan.md` — главный документ: план из 15 этапов,
  «Карта прогресса», правила запусков, глоссарий, системные наблюдения и
  accessibility-карты платформ.
- `docs/knowledge/` — свод знаний: selector guide, hard limits, runbook,
  правила фиксации результатов, предусловия окружения. Точка входа —
  `docs/knowledge/README.md`.
- `harness/` — воспроизводимый контур прогона: манифесты кейсов, адаптеры
  приложений, отчёты, selftest.
- `tools/` — oracle, fixtures и fault-профили полигона.
- `mobile-qa-agent/` — собственный агент этапа 14: skill, контракт, evals.
- `evidence/stage-N/<platform>/` — скриншоты и артефакты по этапам плана.
  В отличие от полигона, evidence здесь версионируется.
- `evals/reports/` — отчёты оценочных прогонов.

## Текущий статус

На 7 августа 2026 года план из 15 этапов завершён с формальным verdict
**`PIVOT`**. В ledger находятся 89 записей: 71 `PASS`, 12 `FAIL`, 5 `BLOCKED`
и 1 `INCONCLUSIVE`; 56 на iOS и 33 на Android. Это не один однородный
benchmark: `evidenceComplete: true` имеют 64 записи, `false` — одна, а 24
legacy-записи не содержат этого поля.

Долги 10.1 и `R-19` закрыты. Для одного короткого run измерено `A=4`, `B=0`,
`C=15`, всего 19 человеко-минут, но экономия относительно 270 минут ручного
исследования не доказана: области покрытия несопоставимы. На одном физическом
Samsung SM-S931B / Android 15 зарегистрированы пять попыток (3 `PASS`, 1
`FAIL`, 1 `BLOCKED`), из них четыре зачтённых результата — 3 `PASS` и 1
`FAIL`. Это закрывает исходную неизвестность `R-19`, но не доказывает широкую
поддержку физических устройств и не закрывает полный recovery-набор этапа 4.3.

`evidence/stage-16/` — технический namespace постплановой валидации 4–7
августа, а не новый этап 16. Канонический исторический ход, актуальная карта
прогресса и обоснование verdict находятся в
[плане исследования](docs/testing-learning-plan.md).

Технический статус после CHG-002: QA Lab oracle по умолчанию отделён от fault
proxy (`8890` против `8888`), route сохраняется из context в version manifest,
а proxy проверяется по port/target/PID. Из текущей suite в 202 проверки прошли
176 offline; 26 live-cycle проверок этой ревизии ещё ожидают доступа к
локальному backend. Следующими code debts остаются fresh Workspace,
exception-safe teardown, process ownership и fail-closed `arm`.

## Приложения-стенды

Прогоны выполняются на трёх приложениях, ни одно из которых не разрабатывается
в этом репозитории:

| Приложение | Платформа | Что нужно поднять |
| --- | --- | --- |
| QA Lab Mobile | iOS, Android-эмулятор | backend на `127.0.0.1:8890`, fault proxy приложения `8888 → 8890` (для Android-эмулятора — `10.0.2.2:8888`) и клиент на устройстве |
| QA Lab Mobile | Android, физическое устройство | то же плюс три отличия: разовый `sim-use android init --device <serial>` — без device-bridge `ui` отказывает; сборка `android:device` с `127.0.0.1:8888` вместо `10.0.2.2`, потому что это алиас хоста **внутри эмулятора** и на телефоне не значит ничего; `adb reverse tcp:8888 tcp:8888`, уводящий трафик в USB. Реверс пересоздаётся `expo run`, поэтому шаг обязателен на каждый прогон и входит в `prepare` |
| Speecher | iOS | собранный `.app`, backend не нужен |
| Element X | Android | локальный Synapse на `10.0.2.2:8008` и установленный APK |

QA Lab Mobile, как и два остальных приложения, — внешний стенд. По умолчанию
его отдельный репозиторий ожидается в `../portfolio-site` рядом с этим
репозиторием. Version manifest читает путь из `APP_REPO`, а автоматическая
подготовка QA Lab — из `QALAB_APP_DIR`. Пока это две независимые настройки —
известное несоответствие следующего изменения; для честного version manifest
они должны указывать на один и тот же checkout. Команды сборки и запуска
находятся в документации соответствующего приложения.

Зафиксированные версии окружения (Xcode, AVD, `sim-use`, устройства) — в
этапе 1 плана. Правила старта сессии для AI-агентов — в `AGENTS.md`.
