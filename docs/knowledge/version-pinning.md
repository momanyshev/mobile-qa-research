# Version pinning и upgrade benchmark

## Что фиксируется на каждом run

`harness/lib/versions.mjs` собирает version manifest автоматически, до первого
действия агента. Без него метрики невоспроизводимы, поэтому файл входит в
обязательный evidence pack:

| Поле | Источник | Зачем |
| --- | --- | --- |
| `simUseVersion` | `sim-use --version` | главный измеряемый инструмент |
| `appRepo.commit` + `dirty` | git приложения | что именно тестировали |
| `researchRepo.commit` + `dirty` | git исследования | какой контур измерял |
| `device` | `sim-use devices --json --all` | ID, имя, версия ОС, состояние |
| `agentModel`, `skillRevision` | флаги `--model`, `--skill` | кто и по каким правилам вёл run |
| `node`, `baseUrl` | среда | окружение выполнения |

Флаг `dirty` различает три состояния: `false` — дерево чисто, `true` — есть
незакоммиченные правки, `null` — команда не отработала. Различие существенное:
`null` означает «неизвестно», и выдавать его за «чисто» нельзя.

## Как проверять обновление sim-use

Upgrade benchmark в исследовании **не выполнялся**: версия инструмента не
менялась. Процедура на будущее, выводимая из имеющегося контура:

1. Зафиксировать текущую версию и прогнать `node harness.mjs selftest` — 103
   проверки контура должны пройти без устройства.
2. Прогнать неизменённый набор case на обеих платформах на **той же** сборке
   приложения и том же устройстве: единственная изменившаяся переменная —
   версия инструмента.
3. Сравнить через `harness.mjs summary` по метрикам раздела 10.4, в первую
   очередь: coordinate-free rate, intervention rate, evidence completeness,
   длительность run и число вызовов.
4. Расхождения классифицировать по failure taxonomy. Рост доли координатных
   действий или падение стабильности селекторов — сигнал регрессии инструмента,
   а не приложения.
5. Обновить `docs/sim-use-skill-*.md` и зафиксировать новую ревизию skill в
   `--skill`, чтобы прогоны до и после были различимы в журнале.

Ключевое условие честности сравнения: **менять ровно одну переменную**. Если
одновременно обновились приложение и инструмент, разницу метрик отнести будет
не к чему.

## Почему pinning здесь не формальность

Один из системных выводов исследования — поведение зависит от среды сильнее,
чем ожидается: пустые `LANG`/`LC_ALL` портят кириллицу, непрогретый эмулятор
роняет bridge, отсутствие hardware keyboard молча ломает `paste`. Без
зафиксированного окружения такие эффекты выглядят как случайные флаки и
разрушают доверие к метрикам.
