# Предусловия окружения

Что должно быть верно **до** первой команды прогона. Симптомы уже случившихся
поломок и порядок восстановления — в [../runbook.md](../runbook.md); здесь
только правила подготовки.

Зафиксированные версии (Xcode, AVD, `sim-use`, идентификаторы устройств) — в
этапе 1 `../testing-learning-plan.md`.

## Стенд поднимается командой, а не руками

```bash
node harness/harness.mjs prepare --platform ios --device <UDID> --case <case-id>
```

`start` вызывает `prepare` сам, поэтому отдельно он нужен только для отладки
самой подготовки. Что делает: экспортирует локаль и при необходимости снимает
daemon, поднимает устройство (для iOS — вместе с `Simulator.app`), поднимает
внешний стенд QA Lab (backend 8890 и proxy 8888 → 8890), сбрасывает
fault-профиль, проверяет listener 8081 и при необходимости перезапускает Metro,
запускает приложение и сверяет Workspace прогона. Ограничения этих проверок
владения процессами и фактического URL bundle перечислены ниже.

Путь к внешнему QA Lab задаётся `QALAB_APP_DIR`, а version manifest использует
отдельную переменную `APP_REPO`. Это известное несоответствие следующего
изменения: до исправления обе переменные обязаны указывать на один checkout,
иначе запуск и зафиксированный commit будут относиться к разным исходникам.

Свойства, на которые можно опираться:

- **Идемпотентность.** На готовом стенде не трогает ничего и сообщает
  «изменений не потребовалось».
- **Формальный вердикт о готовности выносит не он.** После `prepare` всегда
  идёт `preflight`. Его `PASS` подтверждает только реализованные проверки, а не
  полное владение процессами или фактический API URL bundle: эти gaps требуют
  ручной сверки ниже.
- **Намерение — не трогать неопознанные процессы.** Но текущая QA Lab-реализация
  считает владельцем backend любой `node` на портах 8890/3999, а Metro — по
  общему имени процесса без проверки cwd/checkout. Это известное
  несоответствие ownership-проверки следующего change; до исправления на
  8081/8888/8890/3999 не должно быть процессов других проектов. Для самого
  observation proxy после CHG-002 readiness уже требует точного совпадения
  порта 8888, target и PID владельца listener.
- **Ничего не удаляет.** Непустой Workspace — отказ, а не автоочистка: данные
  могут быть не наши, а непустота означает, что предыдущий teardown не
  отработал, и это повод разобраться.

Правила ниже `prepare` автоматизирует. Они остаются здесь потому, что
объясняют, **почему** шаги именно такие, и нужны при разборе отказов.

## Metro не переиспользуется между платформами

Базовый URL API зашивается в bundle **платформенной командой сборки**
(`ios:local` → `127.0.0.1:8888`, `android:local` → `10.0.2.2:8888`). Один
процесс Metro, поднятый для iOS, отдаст Android-клиенту iOS-овый URL, и
приложение будет показывать ошибку API при полностью исправном backend.

Переключаясь между платформами: остановить чужой Metro, запустить
платформенную команду заново и **проверить фактический URL в API-инспекторе
приложения** — а не полагаться на то, какая команда была запущена.

## Oracle должен обходить fault proxy

Приложение обращается к proxy 8888, а seed, readState, независимый oracle и
teardown ходят прямо в backend 8890. После CHG-002 это исполняемый default:
один нормализованный `context.baseUrl` используется preflight, seed,
readState, сетевыми oracle checks и teardown; тот же `baseUrl` вместе с
`baseUrlSource` попадает в version manifest. Обязательный workaround через env
больше не нужен.

`ORACLE_BASE_URL` остаётся только необязательным override на другой **прямой**
HTTP backend без path. Локальный адрес observation proxy на порту 8888
отвергается до seed, даже если профиль сейчас `passthrough`; недоступность
direct backend блокирует run без fallback на proxy. Старые evidence не
переписываются: в них 8888 остаётся историческим ограничением конкретного run.

## Android требует явных путей в свежей shell-сессии

Node 22 и Android SDK не лежат в глобальном `PATH`, поэтому нужны

```bash
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
ANDROID_HOME="/Users/maksim/Library/Android/sdk"
```

## Локаль до первой команды sim-use

`LANG` и `LC_ALL` в UTF-8 экспортируются **до** первого вызова `sim-use`
в сессии. Daemon наследует локаль при старте: если он поднялся с пустой
локалью, `paste` тихо превращает кириллицу в mojibake (TOOL-LOCALE-001), и
лечится это только перезапуском daemon. Проверка входит в generic-preflight
harness.

## Изоляция и уборка

- Перед каждым экспериментом **MUST** создаваться отдельный Workspace UUID.
- Teardown обязателен при **любом** verdict, включая `BLOCKED` и прерывание.
  Порог MVP по утечкам — ноль (см.
  [safety-and-forbidden-actions.md](safety-and-forbidden-actions.md)).
- Приложение должно смотреть в тот же Workspace, куда пойдёт seed. Расхождение
  тихое: агент видит чужие или пустые данные, oracle — свои, и результат
  выглядит как «дефектов нет». Проверка встроена в preflight адаптера `qalab`.
  Текущий `prepare` без закреплённого `--workspace` делает обратное: читает UUID
  с экрана и подменяет им сгенерированный контекст. Это **известное
  несоответствие реализации**, а не новое правило. Teardown очищает данные
  завершённого run, но не заменяет namespace isolation. До исправления
  compliant-run создаёт UUID через `new-workspace`, задаёт его приложению и
  передаёт `start --workspace <UUID>`; несовпадение должно блокировать старт.

## Relaunch и crash awareness

Намеренный перезапуск приложения сопровождается `sim-use app-state --reset`.
Без этого crash-baseline предыдущего прогона остаётся в силе и либо даёт ложный
`PROCESS DISAPPEARED`, либо, наоборот, маскирует настоящий crash.

## iOS Simulator должен быть запущен как приложение

Устройство, загруженное без `Simulator.app`, оказывается в headless-состоянии
без дисплея: `simctl io … screenshot` отвечает `Device does not have a
'default' display port`, `sim-use ui` — `No translation object returned`, а
запуск приложения падает с `FBSOpenApplicationServiceErrorDomain code=5`.
Порядок: `open -a Simulator`, затем `shutdown` + `boot` того же устройства.
Одного запуска `Simulator.app` поверх уже загруженного устройства недостаточно.
