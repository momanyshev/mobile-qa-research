# Ограничения, которые не решаются prompt-инжинирингом

Самый ценный раздел для того, кто будет строить агента: список того, где
переформулировка задания **не поможет**. Каждое ограничение подтверждено
экспериментом.

## 1. Нет звука на симуляторе

`sim-use` не подаёт аудио на iOS Simulator. Для Speecher это означает, что
**основной сценарий приложения — диктовка голосом — недостижим в принципе**.
Все пять сценариев этапа 12 намеренно немикрофонные.

Обход: тестировать смежные пути (разрешения, состояние, настройки) и честно
фиксировать, что ядро функции не покрыто. Убрать ограничение может только
подача аудио в устройство, а это вне возможностей инструмента.

## 2. Шифрованное содержимое недоступно oracle

Matrix шифрует тела сообщений. Из базы сервера видно, что событие
`m.room.encrypted` произошло, но **не видно текста**. Никакой промпт этого не
меняет.

Граница проведена явно: «комната создана с таким именем и топиком» проверяется
точно (state-события не шифруются), «в сообщении такой текст» — только по UI,
без независимого подтверждения.

## 3. Транзиентное состояние не доказуемо финальным evidence

Alert, тост, индикатор загрузки живут только во время run. В финальном outline
их уже нет, поэтому факт показа **невозможно** доказать обязательным пакетом
артефактов.

Решение принято конструктивно, а не промптом: такие проверки объявляются как
`manualChecks` и без явного `--confirm-manual` дают `INCONCLUSIVE`, а не тихий
PASS. Альтернатива — видеозапись run, но это ослабляет автоматизм verdict.

## 4. Платформенные picker'ы без доступного значения

iOS wheel-picker не отдаёт label, value и ID (AX-IOS-003). Агент не может
прочитать выбранное значение из дерева — только выставить его действием и
подтвердить через backend.

Это ограничение **приложения и платформы**, снимается только изменением
приложения (доступный control с именем и значением), не промптом.

## 5. Жесты не имеют целевого элемента

Прокрутка и свайп по природе адресуются координатами: у жеста нет контрола, на
который можно сослаться. Поэтому метрика coordinate-free никогда не будет 100%
в сценариях с прокруткой, и требовать этого от агента бессмысленно.

Формулировка gate уточнена: считаются координатные **тапы по контролам**, а
свайп прокрутки — отдельный, допустимый случай.

## 6. Локализованные подписи как селекторы

Если у приложения нет стабильных ID, селектор завязан на видимый текст. Смена
языка внутри сценария обесценивает собственные селекторы run'а. Промпт может
предписать «переснимать дерево после переключения», но не может сделать
селектор устойчивым — это требование к приложению.

## 7. Чистый контекст нельзя сымитировать промптом

Измерение автономности агента (этап 8), recall на посеянных дефектах (этап 9.3)
и pilot-метрики (10.1–10.3) требуют агента, **не знающего** приложение. Модель,
которая вела исследование, знает его слишком хорошо; инструкция «забудь, что ты
видел» не создаёт чистого контекста и не делает измерение честным.

Поэтому все перечисленные измерения стянуты к этапу 14, где чистый контекст
собственного агента естественен. Это методологическое, а не техническое
ограничение — и самое важное в списке.

## 8. Окружение остаётся источником отказов

За 41 прогон встретились: сон машины посреди run, системный overlay Gboard,
падение bridge на непрогретом эмуляторе, молчаливая потеря персистентности
blobs, отсутствие push-шлюза у локального сервера. Ни один из этих классов не
устраняется формулировкой задания — только runbook, детерминированные
предусловия и честная классификация `BLOCKED`.
