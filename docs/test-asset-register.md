# Test asset register (сквозной процесс, этапы 3–7)

Классификация полезных проверок и наблюдений, найденных за этапы 3–7, по
категориям сквозного процесса плана. Это выполнение пункта 9 «Общего Definition
of Done» этапа 7, ранее не сделанного. Источники: карты accessibility (этап 3),
практика действий (этап 4), состояние/восстановление (этап 5), UI↔API и proxy
(этап 6), 24 сценарных run'а (этап 7), таблица «Системные наблюдения».

Правило: сам факт обнаружения не обязывает автоматизировать. Ниже — обоснованная
классификация и backlog, а не готовый регрессионный набор (это соответствует
scope MVP).

Категории (из плана):

- **TC** — отдельный тест-кейс (критическая, повторяемая, многоусловная);
- **CL** — чек-лист (короткая, однозначная);
- **AUTO** — кандидат на автоматизацию (стабильные данные/действия + независимый
  oracle);
- **CH** — exploratory charter/эвристика (зависит от контекста);
- **DEV** — device-specific чек-лист (значима только на физическом устройстве);
- **MAN** — ручная проверка с зафиксированным ограничением (нестабильна/нет
  надёжного oracle);
- **APP** — требование к тестопригодности приложения (blind spot accessibility).

## A. Функциональные проверки приложения (из сценариев этапа 7)

| # | Проверка | Платформа | Категория | oracle | Обоснование |

| A1 | Создание дефекта: ровно 1 запись с точными полями, POST 201, без дублей | iOS+Android | **TC + AUTO** | `expectCount`+`expectFields`, request log | Критическая, повторяемая, стабильный API-oracle |
| A2 | Редактирование: изменяется только целевое поле; id/createdAt сохранены; updatedAt растёт | iOS+Android | **TC + AUTO** | `expectOnlyChanged` | Ловит незамеченные мутации (поймано на 7.5) |
| A3 | Переход статуса open→in_progress из карточки | iOS+Android | **TC** (AUTO — только Android) | `expectFields` | На iOS wheel-picker нестабилен для авто (см. C) |
| A4 | Удаление названного дефекта: 404, соседние не тронуты, DELETE 204 | iOS+Android | **TC + AUTO** | `expect404`+`expectCount` | Destructive, повторяемая, надёжный oracle |
| A5 | Search + мультифильтры: UI-результат == независимый API-query | iOS+Android | **TC + AUTO** | сравнение с API-query | Многоусловная, детерминированный оракул |
| A6 | Изоляция Workspace: нет утечки A↔B, возврат в A восстанавливает данные | iOS+Android | **TC + AUTO** | `expectWorkspaceIsolation` | Критическая для partition-модели |
| A7 | Несохранённые изменения: Alert показан, черновик жив после «Продолжить», отмена не создаёт POST | iOS+Android | **TC** | `expectCount`=0 + распознавание Alert | Alert по тексту (iOS без role) — оракул полунадёжен |
| A8 | Persist Workspace/темы после relaunch; background/foreground не теряет state | iOS+Android | **CL + AUTO** | сравнение значения до/после | Короткая, детерминированная |

## B. Blind spots accessibility → требования к тестопригодности (APP)

| # | Наблюдение | Платформа | Категория | Требование к приложению |
| --- | --- | --- | --- | --- |
| B1 | Native Picker статуса/severity не отдаёт label/value/ID в raw tree (AX-IOS-003) | iOS | **APP + MAN** | Доступный платформенный control с именем, бизнес-значением и ID |
| B2 | Роли нестабильны: header/checkbox/alert/summary/progressbar теряются или меняются между снимками | iOS | **APP** | Стабильные accessibility roles; проверить RN/iOS mapping |
| B3 | Активная вкладка без `selected` state (AX-IOS-001) | iOS | **APP** | Передавать selected-state таб-контрола |
| B4 | Коллизии label: два «Закрыть»/«Создать дефект»/«Удалить» без ID | iOS+Android | **APP + MAN** | Уникальные accessible name или testID для конфликтующих контролов |
| B5 | Содержимое code-block (тело ответа, cURL) недоступно в tree (AX-IOS-009/AX-ANDROID-003) | iOS+Android | **APP + MAN** | Доступное value или безопасный экспорт содержимого |

## Сводка backlog

- **Кандидаты на UI-автоматизацию (AUTO):** A1, A2, A4, A5, A6, A8, A9 + D1 —
  стабильные данные/действия и независимый API-oracle. Приоритет: A2 и A6
  (ловят тонкие дефекты мутаций и изоляции).
- **Тест-кейсы (TC):** A1–A12, D1–D3 — многоусловные, повторяемые.
- **Чек-лист (CL):** A8, A9 — короткие детерминированные.
- **Ручные/эвристики (MAN/CH):** A3(iOS), A7, B1, B4, B5, C1–C6 — нет надёжного
  автоматического оракула или зависят от контекста.
- **Требования к тестопригодности (APP):** B1–B5 — переданы в backlog
  приложения (полигон).
- **Device-specific (DEV):** D4 — ждёт физического устройства.

Не входит в MVP: реализация регрессионного набора. Результат этапа —
обоснованная классификация и backlog.
