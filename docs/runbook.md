# Runbook: диагностика и восстановление sim-use

Практическая инструкция агента: `симптом → вероятная причина → восстановление →
нужна ли эскалация`. Составлена по наблюдениям этапов 1–5 на QA Lab Mobile
(iOS Simulator и Android Emulator). Пороговое правило по всему runbook: **не
более трёх попыток одного действия**; после третьей неудачи — остановка, сбор
доступного evidence и эскалация. `ok:true` инструмента никогда не является
доказательством результата — только независимый UI/API-оракул.

## Общие правила остановки (stop conditions)

- **Неожиданный crash** (блок `PROCESS DISAPPEARED`): агент останавливается,
  сохраняет последний UI/API-стейт и screenshot, **не перезапускает приложение
  молча**. Relaunch — только как явное решение с последующим
  `app-state --reset`.
- **Три безрезультатные попытки** одного бизнес-действия: остановка и эскалация
  человеку с собранным evidence. Смена selector/координат считается новой
  попыткой того же действия.
- **Destructive action** (удаление, `pm clear`, очистка данных, массовая
  мутация): только как явно запланированный обратимый шаг; иначе — остановка и
  запрос подтверждения.
- **Потеря контроля**: неизвестный экран, потеря связи с устройством,
  неожиданный системный диалог, расхождение UI и API — остановка, не повторять
  потенциально опасное действие «на всякий случай».

## Кросс-платформенные симптомы

| Симптом | Вероятная причина | Восстановление | Эскалация |
| --- | --- | --- | --- |
| `Selector matched N elements` / `multipleMatches` | Label делят контейнер и его дочерний текст либо повторяющиеся кнопки | Уточнить `--element-type`, `--frame` или свежий alias; координаты не нужны | Нет, если однозначный selector найден |
| `tap @N` попал не туда (`ok:true`, эффекта нет) | Stale alias: дерево изменилось после навигации | Всегда `ui` перед tap; повторить по свежему алиасу | Нет |
| `No matching element` сразу после открытия экрана | Анимата ещё идёт, элемент не в дереве | `--wait-timeout N` (ждать появления) вместо фиксированного `sleep` | Нет |
| `ok:true`, но постусловие не выполнено | Tap в системную зону (status bar / нав-бар) или устаревшее состояние | Проверять постусловие; вывести контрол в середину экрана прокруткой | После 3 попыток — да |
| Submit «прошёл», но мутации нет | Клиентская валидация формы блокирует отправку | Проверить обязательные поля; подтверждать мутацию через API | Нет |
| Unicode/русский текст превратился в mojibake после `paste` (напр. 67 симв. → 127) | daemon стартовал с пустой/не-UTF-8 локалью — **типично для свежего shell, где `LANG` и `LC_ALL` не заданы** (TOOL-LOCALE-001) | Экспортировать `LANG=LC_ALL=…UTF-8` **до** первой sim-use-команды сессии; если daemon уже поднят — `sim-use daemon stop` и повторить paste с `--replace` | Нет |
| Wheel-picker (критичность/статус) перелетает при свайпе (medium→blocker одним свайпом) | RN-колесо инерционно, свайп несёт импульс (TOOL-PICKER-001) | Управлять **тапом по строке, соседней с центром**: ровно один шаг за тап; не свайпать колесо вслепую | Нет |
| `paste` (HID Cmd+V) молча не вставил на iOS Simulator | Нет подключённой hardware keyboard — HID-события игнорируются (ENV-HWKB-001); RN `TextField` не отдаёт iOS edit-menu, поэтому `--via-menu` тоже не срабатывает | `defaults write com.apple.iphonesimulator ConnectHardwareKeyboard -bool true` (или Simulator I/O → Keyboard → Connect Hardware Keyboard), затем `paste` | Нет |
| Значение поля не то, что вводили | HID-гонка/трансформация поля (autocapitalize) | Пауза ~2 c после фокуса; читать итог из `ui --json` | Нет |
| Блок `PROCESS DISAPPEARED` | Crash или внешнее завершение процесса | Остановиться, сохранить evidence; relaunch только явно + `app-state --reset` | **Да**, если crash не спровоцирован сценарием |
| `... is not reachable via adb` / устройство пропало | Устройство не загружено/отключено/неверный serial | `adb devices` / `sim-use devices`, дождаться `device`, повторить | Да, если устройство не поднимается |
| Команды внезапно медленные/висят | daemon остановлен или устарел | `daemon status`; следующая команда авто-respawn; при зависании `daemon stop` + повтор | Нет |

## iOS Simulator

| Симптом | Вероятная причина | Восстановление | Эскалация |
| --- | --- | --- | --- |
| Tap по контролу в верхнем правом углу открывает Expo dev menu | Плавающая кнопка Expo dev-client (`gearshape.fill`, AX-ENV-001) лежит поверх контрола | Закрыть меню `#xmark`, затем **оттащить кнопку** свайпом с удержанием (`swipe --from <центр gear> --to <свободное место> --duration 1.0`) — подтверждено, контрол под ней становится доступен. Присутствие кнопки непостоянно (на части устройств её нет); в production-сборке отсутствует | Нет |
| Первый запуск перекрыт Expo dev menu | Первый старт dev-client | `Continue`, затем `Close` (`#xmark`) до основного экрана | Нет |
| `paste` «молча» ничего не вставил | Soft-keyboard-only режим, HID Cmd+V игнорируется | Подключить hardware keyboard, либо `paste --via-menu` (кроме нелатинских локалей), либо `--stdin` после проверки локали | Нет |
| `paste --via-menu` не находит пункт меню | Локаль устройства не английская («Выбрать все»/«Вставить») | Использовать HID-путь `paste`/`--replace` | Нет |
| `type` даёт не те буквы (`x`→`ч`) | Активный язык раскладки устройства искажает HID | Переключить раскладку устройства на English (с подтверждением) или использовать `paste` | Нет |
| `keyboard-state` не меняется / поле не фокусируется | Tap в мёртвую зону или мимо поля | Свежий `ui`, tap по актуальному алиасу/ID, пауза | Нет |
| Управление Simulator (клавиатура, поворот) не работает | Нужен macOS Accessibility для хост-приложения | Выдать доступ в System Settings → Privacy → Accessibility, либо ручной шаг оператора | Да, если доступ не выдан |
| `simctl io … screenshot` → `Device does not have a 'default' display port`; `sim-use ui` → `No translation object returned`; запуск приложения падает с `FBSOpenApplicationServiceErrorDomain code=5` | Симулятор загружен **без запущенного Simulator.app** — headless-состояние без дисплея | `open -a Simulator`, затем `simctl shutdown` + `simctl boot` этого же устройства; одного лишь запуска Simulator.app поверх уже загруженного устройства недостаточно | Нет |
| `PROCESS DISAPPEARED` про **чужое** приложение при работе с целевым | Crash-baseline остался от приложения предыдущего прогона | Игнорировать для своего приложения, но не сбрасывать чужой baseline своей волей; чистить между прогонами, иначе реальный crash будет замаскирован | Нет |

## Android Emulator / устройство

| Симптом | Вероятная причина | Восстановление | Эскалация |
| --- | --- | --- | --- |
| `android type` пишет в предыдущее поле | Целевое поле было за soft keyboard, tap не сфокусировал его | Заполнять по одному: поле → tap следующего поля → ввод; сверять `ui --json` | Нет |
| В поле «сам собой» появился лишний текст после свайпа (67 → 70 символов, дописалось « to») | Свайп прошёл над открытой клавиатурой и был распознан Gboard как **glide-ввод** (TOOL-ANDROID-GLIDE-001). Ошибка тихая: `ok:true`, видно только по значению поля | Перед любым свайпом проверять `keyboard-state`; прокручивать только при `hidden`; после ввода сверять значение поля, а не только факт `ok` | Нет |
| `button back` вместо скрытия клавиатуры открыл диалог несохранённых изменений | На этой сборке один `back` делает и то, и другое (TOOL-ANDROID-BACK-002) — безопасным способом убрать клавиатуру он не является | Не использовать `back` как «скрыть клавиатуру»; если диалог всё же открылся — «ПРОДОЛЖИТЬ РАБОТУ» и продолжать тапами по полям | Нет |
| На свежем эмуляторе `android init` → `Bridge transport error`, затем bridge однажды перезапускается (`PROCESS DISAPPEARED`) | Init выполнен до полной загрузки системы (TOOL-ANDROID-BRIDGE-003); блок относится к самому bridge, а не к приложению под тестом | Дождаться `adb shell getprop sys.boot_completed` = 1, повторить `android init`; после перезапуска bridge проверить дерево `ui` | Нет |
| `sim-use ui` → `root_window_timeout`, bridge-screenshot отказывает по rate limit | Поверх приложения системный диалог, часто «System UI isn't responding» на свежем эмуляторе (ENV-ANDROID-ANR-004) | Снять экран независимо: `adb exec-out screencap -p > f.png`; закрыть диалог кнопкой «Wait»; затем повторить `ui` | Нет |
| `android paste` → `clipboard_write_failed` | AccessibilityService не может писать clipboard | Использовать `android type --clear`; для Unicode — тоже `type` | Нет |
| app-scoped `ui` внезапно пуст, `type` → `no_focused_input` | Системный overlay (Gboard onboarding, «Try out your stylus» и т. п.) поверх приложения (AX-ANDROID-005) | `adb exec-out screencap` для диагностики (обычный screenshot тоже может быть перекрыт); закрыть overlay координатным tap после визуального подтверждения; повторить | Нет |
| Клиент Matrix не находит локальный homeserver, запросов на сервер нет | Адрес введён без схемы — Element X молча игнорирует `host:port` (ENV-EX-001) | Указывать схему явно: `http://10.0.2.2:8008`. Cleartext HTTP при этом разрешён | Нет |
| Публичную комнату не создать: адрес комнаты помечен невалидным | `server_name` вида `IP:порт` даёт в алиасе два двоеточия (ENV-EX-002) | На таком стенде создавать приватные комнаты либо задать `server_name` без порта | Нет |
| При каждом старте — диалог ошибки уведомлений | У локального homeserver нет push-шлюза (ENV-EX-003) | Гасить диалог первым шагом сценария (`#dialog-positive`); на дефект приложения не списывать | Нет |
| Нижняя Button не срабатывает (`ok:true`, эффекта нет) | Tap ушёл в системную навигационную зону | `--frame maxY=<near-bottom> --element-type Button` | Нет |
| Дерево содержит только видимый экран | Android-tree = viewport; элемент вне экрана «не существует» | Прокрутить до элемента, повторить `ui` | Нет |
| `... bridge` не отвечает / дерево не читается | Bridge APK слетел или устарел | `sim-use android init` (переустановка bridge), проверить `ui` | Да, если init не помогает |
| После `pm clear` приложение на dev-launcher, а не в UI | `pm clear` на dev-client стирает и связь с Metro | Ввести URL Metro (`http://10.0.2.2:8081`) в поле dev-launcher → `Connect`; дождаться бандла; закрыть dev menu | Нет; на production-сборке эффекта нет |
| API error при исправном backend после смены платформы | Переиспользован Metro другой платформы (иной build-time URL) | Остановить чужой Metro; `npm run android:local` с явными `JAVA_HOME`/`ANDROID_HOME`; проверить URL в API-инспекторе | Нет |

## Порядок действий при любом сбое

1. Сделать свежий `ui` — не доверять прошлому снимку.
2. Сверить экран со `screenshot`, если дерево выглядит неожиданно.
3. Проверить постусловие независимым оракулом (UI + API), а не `ok:true`.
4. При исчерпании трёх попыток — сохранить evidence, классифицировать причину
   (`BLOCKED` — окружение/инструмент; `FAIL` — ошибка агента при исправном
   окружении; `INCONCLUSIVE` — недоказуемое состояние) и эскалировать.
