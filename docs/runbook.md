# Runbook: диагностика и восстановление sim-use

Практическая инструкция агента: `симптом → вероятная причина → восстановление →
нужна ли эскалация`. Основа собрана на этапах 1–5 (iOS Simulator и Android
Emulator), дополнения для физического Android внесены 7 августа 2026 года.
Пороговое правило по всему runbook: **не более трёх попыток одного действия**;
после третьей неудачи — остановка, сбор доступного evidence и эскалация.
`ok:true` инструмента никогда не является доказательством результата — только
независимый UI/API-оракул.

## Общие правила остановки (stop conditions)

- **Неожиданный crash** (блок `PROCESS DISAPPEARED`): сначала проверить
  названный процесс и строку классификации `[harness]`. Целевой или неясный
  процесс означает остановку с сохранением последнего UI/API-стейта и
  screenshot; **молчаливый relaunch запрещён**. Только подтверждённый чужой
  процесс при живом целевом приложении позволяет продолжить с записью события
  в отчёт.
- **Три безрезультатные попытки** одного бизнес-действия: остановка и эскалация
  человеку с собранным evidence. Смена selector/координат считается новой
  попыткой того же действия.
- **Destructive action** (удаление, `pm clear`, очистка данных, массовая
  мутация): только как явно запланированный обратимый шаг; иначе — остановка и
  запрос подтверждения.
- **Потеря контроля**: неизвестный экран, потеря связи с устройством,
  неожиданный системный диалог, расхождение UI и API, пустое целевое поле или
  возможная мутация соседнего — остановка, не повторять потенциально опасное
  действие «на всякий случай».
- **Потеря журналирующей обёртки/TCC-доступа**: штатный `harness.mjs abort`,
  если он доступен, затем `BLOCKED/environment`. Прямые незажурналированные
  `sim-use`/`adb`-команды не используются как обход; если abort недоступен —
  остановка и эскалация оператору для обязательного teardown.

## Кросс-платформенные симптомы

| Симптом | Вероятная причина | Восстановление | Эскалация |
| --- | --- | --- | --- |
| `Selector matched N elements` / `multipleMatches` | Label делят контейнер и его дочерний текст либо повторяющиеся кнопки | Уточнить `--element-type`, `--frame` или свежий alias; координаты не нужны | Нет, если однозначный selector найден |
| `tap @N` попал не туда (`ok:true`, эффекта нет) | Stale alias: дерево изменилось после навигации | Всегда `ui` перед tap; повторить по свежему алиасу | Нет |
| `No matching element` сразу после открытия экрана | Анимата ещё идёт, элемент не в дереве | `--wait-timeout N` (ждать появления) вместо фиксированного `sleep` | Нет |
| `ok:true`, но постусловие не выполнено | Tap в системную зону (status bar / нав-бар) или устаревшее состояние | Проверять постусловие; вывести контрол в середину экрана прокруткой | После 3 попыток — да |
| Submit «прошёл», но мутации нет | Клиентская валидация формы блокирует отправку | Проверить обязательные поля; подтверждать мутацию через API | Нет |
| Unicode/русский текст превратился в mojibake после `paste` (напр. 67 симв. → 127) | daemon стартовал с пустой/не-UTF-8 локалью — **типично для свежего shell, где `LANG` и `LC_ALL` не заданы** (TOOL-LOCALE-001) | Экспортировать `LANG=LC_ALL=…UTF-8` **до** первой sim-use-команды сессии; если daemon уже поднят — `sim-use daemon stop` и повторить paste с `--replace` | Нет |
| Wheel-picker (критичность/статус) перелетает при свайпе (medium→blocker одним свайпом) | RN-колесо инерционно, свайп несёт импульс (TOOL-PICKER-001) | Управлять **тапом по строке, соседней с центром**: ровно один шаг за тап; не свайпать колесо вслепую | Нет |
| `paste` (HID Cmd+V) молча не вставил на iOS Simulator | Нет подключённой hardware keyboard — HID-события игнорируются (ENV-HWKB-001); RN `TextField` не отдаёт iOS edit-menu, поэтому `--via-menu` тоже не срабатывает | `defaults write com.apple.iphonesimulator ConnectHardwareKeyboard -bool true` (или Simulator I/O → Keyboard → Connect Hardware Keyboard), затем `paste` | Нет |
| Значение целевого поля не то, что вводили, либо изменилось соседнее | HID-гонка, трансформация поля или фактический фокус остался в другом поле (R-65) | Проверить полное `value` цели и соседей/связанный счётчик. Возможная соседняя мутация = потеря контроля: сохранить evidence и остановиться, не «чинить» форму новым вводом | **Да, сразу** |
| Свайп «просто прокрутить список» изменил данные | Инлайн wheel-picker внутри карточки перехватил вертикальный жест и закоммитил новое значение (R-27). Ошибка тихая: `ok:true`, баннер легко пропустить | Перед прокруткой смотреть, нет ли колеса в полосе жеста; прокручивать по краю экрана (`x` у самой границы контента), а не по центру; после прокрутки сверять состояние оракулом | Нет |
| После swipe дерево не изменилось | Жест мог быть коротким/вне scroll-view/перехваченным либо снимок устарел (R-67); по одной неизменности причина неразличима | На физическом Android прочитать как минимум следующий `ui`; при расхождении брать более позднее наблюдение и сверять screenshot. Ни два, ни три одинаковых снимка не гарантируют свежесть; не менять траекторию по одной неизменности | Да, если позицию нельзя доказать без догадки |
| `Could not connect to http://<LAN-IP>:8081`, приложение осталось в dev-launcher | Хост сменил LAN-адрес (сон ноутбука, переподключение Wi-Fi), dev-client держит закэшированный URL (R-29) | `Enter URL manually` → для iOS Simulator ввести `http://127.0.0.1:8081`; проверить фактический адрес `ipconfig getifaddr en0` | Нет |
| Блок `PROCESS DISAPPEARED` | `sim-use` сообщает об исчезновении любого наблюдаемого процесса, не обязательно приложения под тестом (R-59/R-64) | Проверить имя пакета и строку `[harness]`: target/unclear → остановка и evidence; подтверждённый foreign при живом target → продолжить и отразить в отчёте. Relaunch только явно + `app-state --reset` | **Да** для target/unclear |
| `... is not reachable via adb` / устройство пропало | Устройство не загружено/отключено/неверный serial | `adb devices` / `sim-use devices`, дождаться `device`, повторить | Да, если устройство не поднимается |
| Команды внезапно медленные/висят | daemon остановлен или устарел | `daemon status`; следующая команда авто-respawn; при зависании `daemon stop` + повтор | Нет |

| --- | --- | --- | --- |

Не сбрасывать чужой baseline своей волей | Нет |

## Порядок действий при любом сбое

1. Сделать новое наблюдение — не доверять прошлому снимку. После swipe на
   физическом Android прочитать как минимум следующий `ui`, не считая никакое
   фиксированное число чтений доказательством свежести.
2. Сверить экран со `screenshot`, если дерево выглядит неожиданно или действие
   зависит от координат.
3. Проверить постусловие независимым оракулом (UI + API), а не `ok:true`.
4. При исчерпании трёх попыток — сохранить evidence, классифицировать причину
   (`BLOCKED` — окружение/инструмент; `FAIL` — ошибка агента при исправном
   окружении; `INCONCLUSIVE` — недоказуемое состояние) и эскалировать.
