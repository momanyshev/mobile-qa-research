Agent self-report: Постусловие достигнуто ЧАСТИЧНО на физическом Samsung SM-S931B. Запись создана: заголовок, тип «Дефект», критичность «Высокая», статус «Открыт» — верны. Описание НЕ равно заданному: к нему слитно приклеился текст, вводившийся в поле «Шаги для воспроизведения». Проверено оператором по backend — расхождение подтверждено независимо.

Главное расхождение (категория sim-use): тап и дерево сообщают о фокусе, которого нет. Тап по #issue-steps-input вернул успех, два подряд ui показали у этого поля флаг focused, android type вернул «type ok (graphemes=98)» — и все три сигнала оказались ложными: поле шагов осталось пустым (скриншот: пустая рамка плюс ошибка валидации), а текст ушёл в поле «Описание», где фокус фактически остался. Повторный тап по тому же ID после прокрутки сработал корректно. Практический вывод: флаг focused не доказательство, «type ok» подтверждает отправку графем в IME, но не адресата; единственная надёжная проверка — value в дереве после ввода или счётчик символов приложения.

Второе расхождение: дерево доступности отстаёт от экрана на ЦЕЛЫЙ экран содержимого, без действий между снимками. Наблюдался случай, где два подряд ui совпали (правило двух совпадающих снимков соблюдено), а третий, тоже без действия, отличался целым экраном. Правило двух снимков этот случай не ловит; различить помогает только скриншот. Признак «дерево после свайпа не изменилось» неоднозначен: означает и выход жеста за scroll-view, и неуспевшее дерево.

Расхождения приложения с самозаявлениями:
- Обязательность полей «Шаги», «Ожидаемый результат», «Фактический результат» нигде не заявлена: ни звёздочек, ни слова «обязательно». Подсказки говорят только о диапазоне длины. Три ошибки появляются разом после нажатия «Создать».
- Список не показывает шаги и результаты — проверить их через UI списка нельзя.
- Тап по заголовку записи в списке не открывает карточку, дерево после тапа идентично, тогда как лендинг заявляет «Создавайте, просматривайте, редактируйте и удаляйте записи».

New knowledge о физическом устройстве против эмулятора:
- Программная клавиатура Samsung съедает больше половины экрана: скролл-вью модалки ужимается с 1655 до 773 px, форму приходится проходить 4-5 свайпами, поля постоянно уходят из viewport, и tap по стабильному ID падает с «No matching element». На эмуляторе прокруток заметно меньше.
- Sticky-футер «Отмена/Создать» при поднятой клавиатуре остаётся доступен, а поля между ними — нет.
- android type передаёт кириллицу без потерь при LANG/LC_ALL=en_US.UTF-8, graphemes совпал со счётчиком символов приложения.
- Крашей приложения под тестом не было; строка [harness] Сигнал о крахе не появлялась ни разу, посторонние процессы себя не проявили.
- Посреди прогона пропал доступ к каталогу ~/Documents целиком (Operation not permitted, EPERM uv_cwd), при полностью исправном adb. Из-за этого финальная верификация выполнялась прямыми adb-командами мимо журналирующей обёртки — эти шаги в transcript отсутствуют, метрики за них неполны. Класс отказа реальной macOS-машины с TCC, невозможный на CI-стенде.

Ошибка самого агента, заявлена честно: в одной bash-строке склеены tap и type через «;». Тап упал (поле вне viewport), а type всё равно выполнился и дописал текст в сфокусированное соседнее поле. Исправлено через android type --clear, проверено скриншотом. Впредь только && между тапом и вводом.

Failure category: sim-use (недостигнутая часть постусловия — ложные сигналы фокуса) и environment (обрыв доступа к каталогу репозитория на этапе верификации).

Чего не проверял: содержимое полей «Шаги», «Ожидаемый результат», «Фактический результат» в сохранённой записи через UI — список их не показывает, карточка не открывается; действия над записью (редактировать/удалить) — карточка до конца не прокручивалась; список вариантов статуса — спиннер не открывался, соответствие «Открыт» → open выведено из подписи.

Follow-up decision: состояние приложения намеренно не правилось. Описание можно было отредактировать, но только в обход сломанного канала sim-use; тихая правка вне журналируемого канала стёрла бы из измерения ровно то расхождение, ради которого прогон делается. Draft дефекта «текст из поля Шаги попадает в Описание» уходит на ревью человеку с оговоркой: нужно проверить руками, воспроизводится ли это без IME-ввода sim-use — от этого зависит, дефект это приложения или инструмента.
