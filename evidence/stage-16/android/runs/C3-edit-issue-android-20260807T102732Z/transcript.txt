Подтверждения: карточка списка показывает «Критичность: Блокер»; в модалке просмотра бейдж имеет идентификатор :issue-badge-severity-blocker:, то есть значение именно blocker, а не похожая подпись; баннер «Запись обновлена.».

Прочие поля сверены после сохранения и не изменились: тип «Дефект» (в форме поле disabled с подписью «Тип записи нельзя изменить после создания»), название, описание, шаги, ожидаемый и фактический результат, статус «Открыт». Изменилось только «Обновлено» 13:27 → 13:32, что производно от правки. Соседняя запись «Опечатка в подписи фильтра» не затронута — её «Обновлено» осталось 13:27. Счётчик «2 записи» не изменился.

Расхождение приложения с самозаявлениями: карточка навсегда остаётся «занято» после сохранения. Контейнер отредактированной карточки получает accessibility-label «занято» (aria-busy) и не сбрасывает его — держится через несколько минут и переживает открытие и закрытие модалки просмотра, при том что все контролы внутри enabled и никакая операция не идёт. У неотредактированной карточки такого контейнера в дереве нет вовсе. Для screen reader карточка бессрочно объявляется занятой. Это второе независимое наблюдение того же дефекта: он уже заявлялся в прогоне M1 на этом же устройстве, где агент честно оговорил отсутствие baseline. Здесь baseline есть — соседняя нетронутая карточка.

New knowledge об инструменте:
- Дерево отстаёт ровно на один вызов ui после прокрутки, и это воспроизводимо, а не разовый сбой. Первый ui после swipe возвращает снимок ДО жеста, второй — актуальный. Поймано скриншотом: ui показывал одну карточку и «конец контента», на экране уже была видна вторая. Симптом идентичен описанному в контракте «жест ушёл вне scroll-view: дерево не изменилось вообще» — по одному дереву эти ситуации неотличимы, и штатная рекомендация «сдвинуть точку старта» дала бы ложный диагноз и лишний свайп. Рабочий приём: после каждого swipe читать ui дважды и брать второй. Применялся весь остаток прогона, расхождений больше не было.
- Координаты в дереве расходятся с реальными сильнее, чем на ~51 pt из контракта: тап по #issue-severity-picker сработал по фактическим (540,1348), тогда как свежее дерево давало y=1747..1908 — расхождение около 400 px. Тап попал точно, потому что sim-use резолвит стабильный ID собственным свежим запросом, а не по координатам из снимка агента. Вывод: на этом телефоне стабильный ID не просто удобнее координат, а единственный надёжный путь — координатный тап промахнулся бы почти гарантированно. То же повторилось на #issue-card-open: тап в (331,997) при дереве, показывавшем 1433.
- Обрезка габаритов по viewport подтверждена численно: Spinner 828x14, кнопка «Сбросить фильтры» 870x11 при нормальной высоте контрола 144-192 px. Высота меньше ~30 px означает, что элемент почти целиком за краем экрана.
- Селектор --label даёт коллизию там, где её не ждёшь: в модалке просмотра две кнопки «Закрыть» (крестик в шапке и кнопка внизу), --element-type Button не помогает, обе Button; --frame maxY тоже не разрулил. Обойдено свежим alias.
- ui --json на этом дереве отдаёт вывод, не парсящийся как цельный JSON, обрывается; для сверки значений использовался человекочитаемый ui. Один вызов ui вернул пустой вывод там, где следующий полный вызов показал нормальное дерево; причина не установлена, отмечено как непроверенное наблюдение.

Отличия от эмулятора: на эмуляторе дерево обычно синхронно с экраном, здесь оно систематически на шаг позади и вдобавок «плывёт» по координатам на сотни пикселей — предположительно следствие живой анимации инерционного скролла на реальном железе, снимок берётся до остановки прокрутки. Программная клавиатура за прогон ни разу не поднялась: ввода текста задание не требовало, ловушка с уходом полей из viewport не проверялась. Сигналов PROCESS DISAPPEARED за прогон не было.

Опасность из контракта подтвердилась структурно: инлайн-Spinner статуса занимает 828 из 972 px ширины карточки (~85%), свайп по центру карточки почти наверняка попал бы в него. Все жесты стартовали по неинтерактивному тексту; непреднамеренных мутаций нет, статусы обеих записей остались «Открыт».

Failure category: неуспеха нет. Единственная упавшая команда — tap --label «Закрыть» с коллизией селектора на шаге закрытия модалки после верификации, не целевое действие, решено с первой альтернативы.

Чего не проверял: полные тексты описания и шагов в дереве обрезаются многоточием — сверялись совпадающие префиксы до и после, а не посимвольное равенство; напрямую через API не сверялся, точное сравнение оставлено oracle.

Follow-up decision: draft дефекта о залипающем aria-busy на отредактированной карточке уходит на ревью человеку, никуда не публиковался. Предложение в свод знаний: правило «после swipe на физическом Android читать ui дважды» — без него неотличимы «жест не сработал» и «дерево отстало», а штатная рекомендация уводит в неверную сторону.
